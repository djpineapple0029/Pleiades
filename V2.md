# AtlasMap V2 — what to change, and what to add

Written 2026-09-13 from an audit of the code as it stood that day: every `.js` file in `frontend/src`, `server/`,
`run.py`, the build scripts, the README and `atlasmap-build-plan.md`. Each item was checked against the source by a
second pass that tried to refute it. Several priorities and recommendations were corrected there, and the text below is
the corrected version. **Line numbers were right on that date and will drift**; the function and constant names are
the stable reference.

The app works well, and the rendering and layout work behind it is careful and documented. Three things stop it being
production-ready, and a fourth makes future edits harder than they need to be:

1. **Work is easy to lose.** The map only exists in tab memory until a manual download, and nothing warns before a reload,
   a tab close or an Open.
2. **The security promise is undone by the transport.** Passwords and plaintext maps cross the network as plain HTTP
   whenever `run.py` is used as intended, from another device on the LAN.
3. **There is no safety net.** There is no version control, the tests exist only in `/private/tmp`, and there is no CI.
4. **Correctness depends on memory.** A 100 KB diary holds the rules that keep the renderer and layout correct, and every
   edit site hand-copies its own sync recipe.

Section 0 is what to do today. Section 1 is the order to do everything in. Section 2 lists every change, with context.
Section 3 lists features, seen from users' side. Section 4 is the list of invariants no change may break.

**Priority:** P0 = data loss, a security hole, or blocks production use · P1 = should be in V2 · P2 = worthwhile ·
P3 = nice to have.
**Effort:** S < ½ day · M 1–2 days · L 3–5 days · XL > 1 week.

## 2. Things to change

### 2.1 Data safety

#### 2.1.1 Unsaved work is lost without warning — P0 · M · revisits a documented decision
**Where:** `atlasmap-build-plan.md:223-224` ("no 'new map' command and no unsaved-changes warning"). No `beforeunload` anywhere in `frontend/src`. `interaction.js` `openMap()` (~314-347) goes from picker to password to `files.open()`, and `files.applyPayload` replaces the graph. Label and notes edits are direct assignments (`interaction.js:240-241`, `:250`) that bump no counter. Physics writes positions without bumping one either.
**Problem:** The only copy of a map is in tab memory. Cmd+R, Cmd+W, closing the window, a browser update restart, or Ctrl+O followed by picking a file and typing its password all destroy everything since the last save, silently. Nothing on screen says the map is unsaved. `graph.revision` cannot serve as a dirty flag: it drives size and tint easing, and it skips text and position changes.
**Change:**
1. `graph.js`: add a separate `contentRevision`, bumped by every mutator including `recluster` (colours are saved data). Add `setNodeText`/`setEdgeLabel` setters that assign in place and bump **only** `contentRevision`, never `changed()`. Route the edit dialogs through them.
2. `physics.js`: bump `contentRevision` when a run starts and when it stops, never per tick.
3. `files.js`: expose `isDirty`, and record `savedRevision` after a successful open, or after a successful save.
   - For a save, record the value read **just before** `files.save()`. Saving doesn't pause editing, and a Balance keeps
     moving nodes while the request is in flight. Those edits must leave the map dirty.
   - Export (Ctrl+E) is not a save and must not clear the flag.
4. `main.js`: `beforeunload` → `preventDefault()` when dirty. Click-to-fly already gives the page sticky activation. Skip the guard under `import.meta.hot`, or every dev reload prompts.
5. Show the state: `document.title = '• map.atlasmap — AtlasMap'` and an `unsaved ·` prefix in the HUD.
6. Confirm before Open replaces a dirty map. Two placements are safe:
   - **Before `controls.unlock()`.** Not between `unlock()` and the `unlock` event: that event arrives asynchronously,
     and `onUnlock` calls `editor.cancel()`, so a confirm opened in that window would read as Esc.
   - **Simpler: after `pickFile()` returns a file and before the password prompt.** Lock is already gone by then, and a
     cancelled picker doesn't nag.

   Either way, the editor cannot show a zero-field panel today (`editor.open` calls `first.focus()` on `undefined`, and
   Enter only commits from an INPUT). Add a confirm mode that focuses the panel itself (`tabIndex = -1`) and treats Enter
   as confirm. Functional text, e.g. title "unsaved changes", note "Opening replaces this map.", hint
   "Enter: open anyway · Esc: cancel".
7. Add **New map**. Chrome will not let a page intercept Ctrl/Cmd+N, Shift+N, T or W, and Alt is excluded by the modifier guard (`interaction.js:450`), so use an unmodified key while locked or an overlay control. It runs the dirty confirm, stops physics, cancels any pending connect, then `graph.load({nodes:[],edges:[]})` → `physics.reset()` → `view.sync()` → `overview.refit()`. `files.js` needs a `clearCredentials()`.
8. Wording: "saved map.atlasmap" is only true once the browser has written the download. Consider "downloaded …".

**Keep:** `graph.load` refills the same Maps. Load order is `physics.reset()` before `view.sync()`. `labels.js` notices label changes by polling `node.label`, so setters must assign in place.

#### 2.1.2 File-flow races: edits during a pending Open are overwritten, and a stuck `busy` flag disables Save — P2 · S
**Where:** `interaction.js` `openMap`: `prompt()` → `endModal()` returns `mode` to idle before `await files.open()`. `main.js` `requestLock` checks only `isModal`, so the user can re-lock and edit during the round trip plus 600k-iteration PBKDF2. `busy` stays true through that window, so Ctrl+S is silently ignored (`interaction.js:269`). `files.pickFile` settles only on `change` or `cancel`; the `cancel` event needs Chrome 113+ or Safari 16.4+.
**Problem:** Work done while an Open is in flight cannot be saved and is replaced when the Open succeeds. On an older or embedded browser, dismissing the file dialog once leaves `busy` set for good, and Save, Open and Export do nothing, with no message.
**Change:**
- Add a `loading` modal state covering the span from pick to result, so there is no re-lock and no edits, and the HUD shows `opening <name>…`.
- Take `busy` only **after** a file is chosen. A pick that never settles then leaks a promise but blocks nothing. Do not add focus or timeout heuristics to detect cancel; they can discard a real selection.
- Replace every silent `if (busy) return` with a status message: "a file operation is still in progress".

#### 2.1.3 Every save is a new download (`map (1).atlasmap`, `map (2)…`) — P1 · M
**Where:** `files.js` `triggerDownload` (~35-44) and `save()` (~87-100). `README.md:126-128` and plan:43 accept the trade-off. `files.js:127` adopts an opened file's name verbatim, so reopening `map (1).atlasmap` saves as `map (1) (1).atlasmap`.
**Problem:** Downloads fills with near-identical copies, the HUD names a file that may not exist under that name, and users reopen a stale copy.
**Change:** Where it exists (Chromium, secure contexts), use the File System Access API.
- First save or Save As: `showSaveFilePicker`. Open: `showOpenFilePicker`. Keep the handle in `files.js`.
- Ctrl+S with a handle: `createWritable()` → write → `close()`. This replaces the file atomically through a swap file.
- **Activation traps.**
  - Call the picker *before* the network round trip; the ~5 s user-activation window is shorter than PBKDF2 plus upload for big maps.
  - The picker drops pointer lock, which fires `onUnlock` and cancels any open editor, so close the editor first.
  - An opened handle has read permission only. The first Ctrl+S must call `requestPermission({mode:'readwrite'})` inside the keydown, before any `await`.
- Warn if `(await handle.getFile()).lastModified` changed since the last write (another tab or app wrote the file).
- An `AbortError` from the picker is a cancel, not a failure.
- Fall back to today's download on Firefox, Safari and `http://<lan-ip>`, which is not a secure context.
- Pairs with 2.2.5 (client-side crypto), but works with server crypto too: write the bytes the server returns.

#### 2.1.4 The app can save a file it will then refuse to open — P2 · S
**Where:** `JSON.stringify` turns `NaN`/`±Infinity` into `null` (`files.js:92`), so `atlasfile.py`'s `allow_nan=False` never fires for browser saves, even though its comment says it prevents unopenable files. `graph.load`'s `requireFinite` rejects `null`, and the whole map is refused. `physics.writeBack` and `graph.addNode` store positions unchecked. One dangling edge also rejects the whole file (`graph.js:232-234`), while self-loops and duplicate edges are dropped silently.
**Problem:** No current code path is known to produce a non-finite position. The forces are softened, and d3 heals a `NaN`, though not an `Infinity`, on the next Balance. But an import feature, a new force or a hand-edited file would create an encrypted map that can never be reopened, and the failure shows up weeks later.
**Change:**
- In `files.save()`/`exportHtml()`, refuse to save a non-finite position with a named message: "node 'Foo' has an invalid position; press B to re-balance".
- Guard `addNode`.
- In `writeBack`, stop the run and restore the last-seed snapshot on the first bad value.
- Optionally give `load` an explicit, reported repair path: place a bad node at its neighbours' centroid, drop dangling edges, and say "opened · 3 problems repaired". Keep strict loading as the default.
- Fix the `atlasfile.py` comment.
- Land this before any import feature or new force.

**Keep:** Never coerce with `Number()`; that silently parks nodes at the origin.

#### 2.1.5 A negative `cluster_color_id` in a file freezes the app (and every export of it) — P2 · S
**Where:** `graph.js:220` accepts any integer. `palette.clusterInk(-1)` indexes `CLUSTER_INKS[-2]`, which is `undefined`. `labels.js` `inkFor` then throws a TypeError inside `view.update`. In three r180 a throw inside `setAnimationLoop` stops the loop for good (`WebGLAnimation` calls the callback before requesting the next frame). There is also a cache-key collision: `tier * 1024 + colorId` collides once colour ids pass 1024, which a map of more than 1024 separate linked pairs reaches through a normal Balance.
**Change:**
- Accept only `Number.isInteger(v) && v >= 0` on load.
- In `clusterInk`, return `null` unless `colorId > 0`.
- Use a collision-free ink cache key, e.g. `colorId * 4 + tier`.
- `load` also counts negative ids as clusters (`.filter(Boolean)` keeps them); fix that too.

#### 2.1.6 No crash recovery — P1 · M
**Where:** Nothing uses IndexedDB, localStorage or a timer save. `README.md:118-119` says "nothing is stored between sessions".
**Problem:** Even with 2.1.1, a renderer crash, OS kill or power loss loses everything since the last manual save. Because every save is a new download (2.1.3), people save rarely. A lost WebGL context alone does *not* lose data: the JS heap and the DOM editor survive, and Ctrl+S still works if the user is told.
**Change:** Keep encrypted drafts, never plaintext.
- *Before* client-side crypto: once a password exists and the map is dirty, debounce ~30 s (and on `visibilitychange` → hidden). Call the existing `/api/save` and store the returned **ciphertext** in IndexedDB instead of downloading it.
- At boot, if a draft exists, show "Recover unsaved map from 14:32 · R". Recovering wraps the bytes in a `File` and runs the normal password prompt and Open.
- Clear the draft on an explicit save or open.
- Give autosave its own in-flight guard; do not reuse `busy`, which would block Ctrl+S.
- A never-saved map (no password yet) stores nothing and relies on `beforeunload`.
- After 2.2.5, derive the key once per session and encrypt drafts locally, so drafts stop costing a PBKDF2 and an upload every 30 s.
- Drafts are per origin. Fix the 5001/5051 port mismatch (2.4.12) or drafts written at one URL look lost at another.

### 2.2 Security, transport and deployment

#### 2.2.1 The password and the whole decrypted map cross the network in plaintext — P0 · S (mitigation) / L (fix)
**Where:** `files.js:89-93` POSTs `{password, filename, payload}` and `files.js:107-113` POSTs the password with the file. `api.py:97` returns the decrypted map, notes included. `run.py:31` binds `0.0.0.0` by default and `run.py:199` has no TLS. `run.py:149-156` advertises `http://<lan>:PORT` and `http://<public-ip>:PORT (needs a port-forward)`. Its docstring says LAN access is the launcher's purpose.
**Problem:** The product's promise is that the password is the only key and is never written anywhere. In practice, every save and open from another device sends the password and every node's notes across the Wi-Fi in the clear. With a port-forward, as the dashboard suggests, anyone on the path can read them. An active attacker can also rewrite the served JavaScript, so client-side crypto alone does not fix this: any non-loopback origin needs HTTPS. `crypto.subtle` (2.2.5) and the File System Access API (2.1.3) also only exist in secure contexts.
**Change:**
1. **Now.** If the bind is non-loopback and no certificate is configured, refuse to start unless `--insecure-lan` is passed, and print a red warning. Remove the "internet … needs a port-forward" line, or replace it with "never port-forward plain HTTP". `python -m server` stays loopback-only.
2. Serve TLS from `run.py`: `make_server(..., ssl_context=(cert, key))` from `ATLASMAP_TLS_CERT`/`ATLASMAP_TLS_KEY`. Document mkcert for the LAN IP and hostname, including that **each phone or tablet must install and trust the mkcert root CA**; otherwise the TLS path looks broken on other devices. For anything beyond one machine, put Caddy with automatic HTTPS in front.
3. Do not rely on HSTS for IP-literal URLs; browsers ignore it there.
4. Long term, 2.2.5 takes the password and plaintext off the wire.

#### 2.2.2 `python -m server` always runs Flask's debug mode, which the README calls the production run — P1 · S
**Where:** `server/__main__.py:14` `debug=True` unconditionally. `README.md:22-27` "Production-style run" uses that same command, and `README.md:29` documents `ATLASMAP_HOST` for widening the bind.
**Problem:** Debug mode renders Werkzeug traceback pages (source and absolute paths such as `/Users/<name>/…`) for any unhandled exception, and several are reachable (2.2.7). It also runs the reloader. The interactive console needs a trusted Host header plus the PIN, which locks after 10 failures with escalating delays, so remote code execution is unlikely. `run.py` does not use debug mode.
**Change:**
- Enable debug only when `ATLASMAP_DEBUG=1`, and refuse debug on a non-loopback bind.
- Relabel the README section "development only", and point production at 2.2.6 or at static hosting (2.2.4).
- Keep `python -m server` working for the Vite dev proxy.
- Add a test that `create_app().debug is False`.

#### 2.2.3 LAN clients can inject terminal escape sequences into the `run.py` dashboard — P2 · S
**Where:** `run.py` `Stats.finish` stores `request.method` and the percent-decoded `request.path` raw. Werkzeug's `unquote` turns `%1b` into ESC, and the method token is never truncated (`{method:4}` only pads). Rows are printed on every Enter redraw. `run.py:193` silences Werkzeug's own logger, which escapes exactly these bytes.
**Problem:** Anyone who can reach the port can repaint the dashboard, e.g. redraw the "Connect from" block with their own IP so the owner opens a lookalike page and types a map password. In some terminals OSC sequences can also set the title or write the clipboard.
**Change:**
- Escape C0/C1 control characters in method, path and client address, the way Werkzeug does.
- Truncate *both* method and path after escaping.
- Add a unit test with `\x1b[2J` and `\x1b]52;c;…\x07`.

#### 2.2.4 Decide whether V2 needs a Python server at all — P1 · M · decision
**Where:** The server holds no graph logic (`server/__init__.py:1-3`, `api.py:1-5`). Its only jobs are about 20 lines of crypto and serving `server/static`. The HTML export already produces a zero-server, `file://`-openable artefact.
**Problem:** Keeping Flask by default costs the Python toolchain, a second dev process, a hard-coded proxy port, the stale-build trap, a production WSGI story and an attack surface (2.2.1–2.2.3, 2.2.6–2.2.8). After 2.2.5, all it adds is `send_from_directory`.
**Options (record the choice as an ADR):**
- **(A) Static site + PWA (recommended default).** `vite build` output goes on any HTTPS static host, or `caddy file-server` on the LAN, plus a service worker for offline use. Headers go in the host config. `viewer-template.html` must stay a same-origin file `files.js` can fetch; generate it through a Vite plugin (2.7.7).
- **(B) Single-file offline editor.** Reuse `build-viewer.mjs`'s inlining to emit `AtlasMap.html`. Verify `isSecureContext` under `file://` in Chrome, Firefox **and Safari** before relying on `crypto.subtle`.
- **(C) Desktop wrapper.** Tauri gives native save dialogs and a small binary, but uses WebKit on macOS and Linux, so re-verify pointer lock, WebGL2 and the `copyTextureToTexture` path in WKWebView. Electron keeps Chromium parity at about 100 MB.
- **(D) Keep Flask** only if a server feature (sync, sharing) is actually planned; then do 2.2.6–2.2.8.

In every option, keep `server/atlasfile.py` as the reference implementation, recovery CLI (2.3.8) and golden-file generator.

#### 2.2.5 Move encryption into the browser (WebCrypto), byte-compatible with v1 files — P1 · L · revisits a documented decision
**Where:** `atlasfile.py:56-78`: PBKDF2-HMAC-SHA256, 600k iterations, 32 bytes → Fernet key; the file is `ATLM` | version | salt(16) | base64url Fernet token. `files.js:50` keeps the raw password string for the whole session.
**Problem:** Server-side crypto forces secrets onto the wire (2.2.1), needs a running server to encrypt a file the user already holds, blocks offline use, and makes encrypted autosave (2.1.6) and encrypted exports (3.x) awkward. Every primitive involved is native in WebCrypto.
**Change:**
1. `frontend/src/format/container.js`, a v1 **reader**.
   - Check the magic and version byte 1; take the salt from bytes 5–21.
   - The token is base64url **with `=` padding**, and `atob` needs `-`→`+`, `_`→`/` first.
   - `deriveBits(PBKDF2, SHA-256, salt, 600000, 256)`. The signing key is the first 16 bytes, the AES key the last 16.
   - Token layout: `0x80 | ts(8) | IV(16) | AES-128-CBC ciphertext | HMAC-SHA256(32)`. Verify the HMAC *before* decrypting, and map a failure to the existing "wrong password or altered" error.
   - Do **not** normalise the password (no NFC). Python raises on lone surrogates, so no v1 file can have one, and `TextEncoder` is compatible.
2. Write the new v2 format (2.3.2) from the client. Never write v1 from JS.
3. Swap `files.save`/`files.open` internals behind their current return shapes (`{ok, error}`, `{ok, wrongPassword, error}`) so `interaction.js` does not change.
4. Optional, and weighed against the documented "fresh salt per save" choice: after the first derivation, hold a non-extractable `CryptoKey` plus the file's salt and drop the password string, using a fresh 12-byte GCM nonce per save. Save As with a new password must re-derive with a fresh salt.
5. If `!window.isSecureContext`, say "Saving and opening need HTTPS or localhost".
6. Cross-test both directions against the committed golden files (2.7.2).

**Keep:** The v1 decoder hard-codes 600000 / SHA-256 / a 16-byte salt forever. Credentials are adopted only after a successful open. Password fields are never trimmed.

#### 2.2.6 No production WSGI server, no timeouts, and unauthenticated endpoints that each cost ~130 ms of PBKDF2 — P1 · S (if the server survives 2.2.4)
**Where:** `run.py:199` `make_server(..., threaded=True)`: Werkzeug's dev server, one thread per connection, no limit, no timeout. `MAX_UPLOAD_BYTES` 64 MiB, and the upload is read fully into memory.
**Problem:** One LAN client can pin every core with `POST /api/open` requests carrying any password, or hold threads open with slow requests. Per-IP rate limiting does **not** improve password security, because an attacker holding the file brute-forces offline; it only helps availability.
**Change:**
- Serve with `waitress` (pure Python): `threads=8`, `channel_timeout=30`, `connection_limit=100`, `max_request_body_size`. The `run.py` Stats hooks are Flask hooks and keep working.
- Put a `BoundedSemaphore(cpu_count)` with `acquire(timeout=2)` → 503 around `encode`/`decode`, released in `finally`.

#### 2.2.7 Several inputs return HTML 500s instead of the JSON error contract — P2 · S
**Where:**

**Change:**
- Map those errors to `FormatError`.

- Add regression tests.
- Keep 401 strictly for wrong password; `files.js` re-prompts only on 401.

#### 2.2.8 No security headers, no Host allowlist, no CSP (app or export) — P2 · S
**Where:** `create_app` adds no header hook; the only header anywhere is `Cache-Control: no-store` on `/api`. `TRUSTED_HOSTS` is unset. `/api/open` accepts multipart, a CORS "simple" type, so any website can POST to `127.0.0.1:5001/api/open` without a preflight. The exported HTML has no CSP, although the README promises "nothing fetched from the network".
**Problem:** Impact is modest today: there is no state, session or cookie to steal, and no `innerHTML` anywhere in `src`. But maps are shared, so their text is untrusted input. One future `innerHTML` would be XSS that reads the in-memory password, and a CSP contains that. For exports, a CSP turns the no-network promise from a build-time regex into a browser-enforced rule.
**Change:**
1. **App.** Send CSP `default-src 'self'; img-src 'self' data: blob:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'`, plus `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `COOP: same-origin`. Built app only; Vite dev injects inline scripts.
2. **`TRUSTED_HOSTS`.** List every host people actually type: `127.0.0.1`, `localhost`, the advertised LAN IP, `<machine>.local`. Otherwise every request, static files included, gets a 400.
3. **Origin check on `/api`.** Compare host and port only; behind a TLS proxy the scheme differs.
4. **Export.** In `build-viewer.mjs`, inject `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'sha256-…'; style-src 'sha256-…'; font-src data:; img-src data: blob:; connect-src 'none'; base-uri 'none'; form-action 'none'">` before the first script.
   - Hash the **exact** text between the tags, including the `\n` prefix and `\n  ` suffix `build-viewer.mjs` writes.
   - The JSON data block is never executed and the title is outside the hash, so a payload splice does not break it.
   - Extend `export_e2e` to assert zero `securitypolicyviolation` events.

#### 2.2.9 Password guidance and password managers — P2 · S · revisits a documented decision
**Where:** `interaction.js:288-295` accepts any non-empty matching password ("a" is valid). `editor.js:94-98` sets `autocomplete='off'` on purpose. `README.md:122-124`: a lost password is unrecoverable. Save As always demands a new password, even just to rename.
**Problem:** PBKDF2-SHA256 at 600k still allows thousands of GPU guesses per second, so short passwords fall quickly to anyone holding the file. The app also discourages the one tool (a password manager) that prevents permanent loss.
**Change:**

- Use `autocomplete="new-password"` on save and `"current-password"` on open, set per field descriptor, not blanket in `editor.js`.
- Save As with a blank password keeps the current one. Add a separate change-password command.
- The real defence against GPU cracking is Argon2id in format v2 (2.3.2).

#### 2.2.10 `run.py` calls a third party on every start, exits without a TTY, and ignores SIGTERM — P2 · S
**Where:** `run.py:123-129` calls `api.ipify.org` on every start. The 3 s timeout does not cover DNS, so offline machines stall longer. `sys.stdin.readline()` returning `''` at EOF shuts the server down immediately under launchd, systemd, `docker run` without `-i`, and many IDE run configurations, exiting 0 with no message. - List all non-loopback IPv4 addresses, not one guess.
- Move to `server/cli.py` with `[project.scripts] atlasmap = "server.cli:main"`, and document `run.py` in the README; today it is not mentioned.

#### 2.2.11 Static serving: no long-lived caching or compression, and a 3.6 MB sourcemap is public — P3 · S
**Where:** Flask already sends `no-cache` + ETag for everything, which is right for `index.html`, but hashed `/assets/*` never get `immutable`. Nothing is compressed: the 727 KB JS and 653 KB template. `vite.config.js:9` `sourcemap: true` publishes `index-*.js.map` (3.6 MB).

#### 2.2.12 No logging, health endpoint, build stamp or container recipe — P2 · M (if the server survives)

### 2.3 File format, persistence and export

#### 2.3.1 The payload has no schema version, and `load()` silently drops unknown fields — P1 · S · **ship before any V2 field**
**Where:** `graph.js:212-222` rebuilds each node from a fixed allowlist, and `:246` does the same for edges; `toPayload` writes only `{nodes, edges, camera}`. The header comment (`graph.js:4-8`) says later fields are "round-tripped verbatim", which only holds for fields known today. `atlasfile.VERSION` pins the container and KDF, not the payload shape.
**Problem:** V2 will add fields: colour override, edge strength, pinned, tags, saved views. A V2 map opened and re-saved in any build without this change loses them, silently and for good. That includes a tab left open across `npm run build`, a second install, or a rollback. Old builds will always strip V2 fields, so the reader has to ship *a release before* the first new field.
**Change:**
1. Top level: `"format": "atlasmap"`, `"schema": 1`, `"app": "<version>"`, optional `"modified"`. A payload without `schema` is schema 1.
2. `frontend/src/format/schema.js`: `CURRENT_SCHEMA` plus a `migrate()` chain run before validation. A newer schema is refused with "made by a newer AtlasMap (schema N)". Check this *before* building anything, so nothing partially commits.
3. Preserve unknown keys per node, per edge and at top level, in a pass-through bag that `toPayload` writes back. Known validated fields always win. Exclude d3-stamped keys (`index`, `vx`…`fz`).
4. Write `docs/FORMAT.md` and a JSON Schema. Rules: new fields are optional with a stated default, fields are never repurposed, renames go through a migration, readers preserve what they don't understand. `VERSION` changes only for crypto or framing, `schema` only for payload shape.
5. Decide `links` (always `[]` today, read nowhere) and `directed` (rendered, since it switches the drift motes, but has no UI) before V2 builds on them.
6. The viewer runs the same `migrate()`.

**Keep:** Validate-then-commit. Refill Maps, never reassign them. Strict `requireFinite`. `cluster_color_id` is authoritative on load.

#### 2.3.2 Specify format v2: KDF parameters in an authenticated header, AES-GCM, no timestamp — P1 · M
**Where:** `atlasfile.py:3-21`: KDF parameters are pinned by the version byte only, and the Fernet token leaks its creation time in plaintext. Base64 inside a binary container wastes a third of the file.
**Change:**
- Layout: `ATLM` | version=2 | kdf_id (1 = PBKDF2-SHA256, 2 = Argon2id) | kdf params | salt(16) | nonce(12) | AES-256-GCM ciphertext+tag.
- Pass the **whole header as GCM additional data**, so any header edit fails authentication.
- Optional gzip before encrypting, flagged in the header. Compress-then-encrypt leaks length, which is negligible for an at-rest file; note it in the spec.
- **Bound every parameter on read**, e.g. PBKDF2 100k–10M; a hostile file declaring 2³² iterations would hang the tab.
- Start with PBKDF2 at 600k. Add Argon2id later via a lazy-loaded, vetted WASM build.
- Keep the v1 reader forever. Old builds already say "version 2 file; this build reads version 1".

#### 2.3.3 The HTML export strips fields by denylist, so any private field V2 adds leaks into plaintext exports — P2 · S · prerequisite of the first new field
**Where:** `files.js:140-147` `nodes.map(({ notes, ...rest }) => rest)`; edges are exported whole.
**Change:**
- Use explicit allowlists in a DOM-free module: nodes `id, label, x, y, z, cluster_color_id, is_core`; edges `id, from, to, directed, label`. Both ids stay, because star appearance and drift-mote phase are hashed from them.
- Add a viewer-visible field to the allowlist deliberately, in the same change that renders it.
- Unit test: `notes`, `secret` and `links: ['https://private']` must not appear in the output.
- Update `README.md:157-161` and plan:1227-1229.

#### 2.3.4 Filename handling is split and partly dead — P2 · S
**Where:** The server's `download_name()` sanitises a header the browser never uses: `files.js` downloads the blob with its own unsanitised name. `setCredentials` only trims and suffixes. An opened `map (1).atlasmap` re-saves as `map (1) (1).atlasmap`. An unsaved map exports as `map.html` without asking.
**Change:**
- Port the rules (and the 14 Python test cases) to `frontend/src/format/filename.js`, and apply them in `setCredentials`, on open and on export.
- Stop sending `filename` to `/api/save`.
- Offer to strip a trailing ` (N)` on Save As.
- Ask for a name when exporting a never-saved map.

#### 2.3.5 Export splicing and `build-viewer.mjs` guards are fragile — P3 · S
**Where:** `files.js:175` replaces the *first* `__ATLASMAP_TITLE__`, then the first `__ATLASMAP_PAYLOAD__`, and the title comes first. A filename containing the payload marker sends the JSON into `<title>`, and the export opens as "This file holds no map". `build-viewer.mjs`:
- `safeForTag` is case-sensitive (`</SCRIPT` passes).
- The tag regexes need double quotes and `type` before `src`.
- The stray-reference scan only sees double-quoted attributes.
- Markers are checked with `includes`, not an exact count.

Escaping today **is** sufficient: `<`→`<` in the JSON block and `escapeHtml` for the title. Record that, so nobody "fixes" it with something weaker.
**Change:**
- Add a pure `spliceTemplate()` that splits on each marker, requires exactly one occurrence, and inserts the payload last.
- `safeForTag`: `/<\/(script|style)/gi`.
- Fail the build on `<!--` in the inlined JS.
- Parse attributes order- and quote-independently.
- Require exactly one of each marker in the HTML and **zero** in the inlined JS.
- Unit-test titles and labels such as `</title><script>`, `__ATLASMAP_PAYLOAD__`, `$&` and `</SCRIPT>`.

**Keep:** Replacement *functions*, not strings, because `$&` appears in both the bundle and the data. Nothing reachable from `viewer.js` may contain a marker literal. The module JS sits in `<head>` *before* the payload tag, so a marker in the JS would be the one that gets filled.

#### 2.3.6 Open asks for a password before checking the file is an `.atlasmap` — P3 · S
**Change:**
- Read `file.slice(0, 21)` first: reject a file that is too short, has the wrong magic, or has a newer version ("made by a newer AtlasMap") before prompting.
- Detect an exported `.html` by name or by a leading `<!doctype`, not by searching for `id="atlasmap-map"`, which sits near the end of a 640 KB file.
- Once crypto is client-side, retries decrypt locally and stop re-uploading the file.

#### 2.3.7 Persistence logic is spread over five files; extract a DOM-free `format/` layer — P2 · M
**Where:**

- Export and splice: `files.js:140-179`.

**Change:** Target structure, moved one module at a time with behaviour unchanged:

- `format/filename.js`.

#### 2.3.8 No offline decrypt/encrypt tool — P2 · S
**Problem:** If a bug or a schema change makes a map unopenable, the user's only recourse is writing Python against an internal module.
**Change:**
- `uv run python -m server.cli decrypt IN.atlasmap [-o OUT.json]` and `encrypt IN.json`.

- Warn that a hand-edited JSON can still be refused by `graph.load` (null positions, dangling edges), pointing to `FORMAT.md`.

#### 2.3.9 Id reuse after reopen, and merge collisions — P3 · M
**Where:** `graph.js:259-260` resumes counters from the highest *remaining* suffix, so deleting `n42` (the highest), saving and reopening makes the next new node `n42` again. Star phase, rate, seed and tint, and edge mote phase, are hashed from ids. `highestSuffix` also hangs the tab (`mintId` loops forever) after loading an id whose suffix is above 2⁵³, e.g. `n99999999999999999999`.
**Problem:** Undo history, deep links, import/merge and sync would all point at the wrong node after an id is reused.
**Change:**
- **Never** rewrite existing ids; appearance is hashed from them.
- Persist `seq: {n, e}` high-water marks (schema-additive).
- Remap colliding ids on merge.
- Mint any new global-style ids with `crypto.getRandomValues`, because `randomUUID` is secure-context-only and would fail on the LAN URL.
- Ignore non-safe-integer suffixes in `highestSuffix`, and bound `mintId`.

#### 2.3.10 Large maps: a file that saves but won't reopen, and main-thread freezes — P3 · S/M
**Where:**
- **Upload limit:** One 64 MB limit applies to both requests. The saved file is base64 Fernet, about 4/3 of the payload, so a 48–64 MB payload saves and then gets a 413 on Open. `json.dumps` keeps `ensure_ascii=True`, so CJK-heavy notes double in size inside the file. The 413 message says "File is larger…" even on save.
- **Duplicate check:** `graph.load` and `addEdge` scan the `from` node's incident set per edge, which is O(Σ deg²).
- **Main thread:** stringify, parse, validation and `view.sync()` all run there.

**Problem:** None of this bites realistic hand-built maps; rendering and layout fail long before 48 MB. It matters once imports exist (F19, F20). The unopenable-save case is still the kind of silent failure this app must not have.
**Change:**
- Estimate the encrypted size before saving (`Blob size × 4/3`) and refuse with a clear message, or make the Open limit ≥ 4/3 × the Save limit.
- `ensure_ascii=False`. Old files still decode, and no `VERSION` bump is needed, but add the golden test first (2.7.2).
- A `Set` of canonical pair keys for the duplicate check.
- Optionally round coordinates to 3 decimals in `toPayload`.
- After 2.2.5, move stringify + encrypt and decrypt + parse into a Worker.
- Add a generated large fixture to the perf suite.

**Keep:** `toPayload` returns copies. The duplicate rules stay undirected, matching `addEdge`.

### 2.4 Architecture and maintainability

#### 2.4.1 No mutation or change-event layer: every edit site hand-copies its own sync recipe — P1 · L
**Where:**
- Spawn: `graph.addNode` + `view.syncNodes()` + `physics.invalidate()` (`interaction.js:168-170`).
- Connect: `addEdge` + `syncEdges` + `invalidate` (`:190-193`).
- Delete: `removeNode` + `clearHover` + `syncNodes` + `syncEdges` + `invalidate`, with a comment warning not to use `sync()` (`:197-206`).
- Core toggle: `setCore` + `invalidate`, with no view call, because the view polls `revision`.
- Text edits: direct assignment with no call at all.
- Load: `graph.load` → `physics.reset()` → `view.sync()` → camera, where order matters.
- Physics writes `node.x/y/z` directly.
- The plan itself warns: "forget it on a new mutation and the layout silently settles the old graph."

**Problem:** Correctness depends on every author choosing the right mix and order of `syncNodes`/`syncEdges`/`sync`/`invalidate`/`reset`, and getting it wrong fails silently. Undo, search, multi-select, dirty tracking, autosave and colour override all need the same thing: one place that performs a mutation and says what changed.
**Change:** Incremental, and each step ships on its own:
1. Add the missing mutators: `setNodeText`, `setEdgeLabel`, `setPositions` (no appearance bump). Add counters: `structureRevision` (add/remove/load), keep `revision` as the **appearance** counter the view already reads (sizes, core, clusters), and `contentRevision` (anything saved).
2. Add a tiny synchronous emitter, `graph.subscribe(fn)`, with typed records: `nodes-added|nodes-removed|edges-added|edges-removed|core|text|clusters|positions|loaded`. **Batch per public command** or with `graph.transaction(fn)`. Today `removeNode` cascades through `removeEdge` and would otherwise emit N+1 events and N+1 full physics reseeds.
3. Physics subscribes: structural and core events → `invalidate()`, `loaded` → `reset()`.
4. View subscribes: node events → `syncNodes()`, edge events → `syncEdges()`, `loaded` → `sync()`. Dispatch `loaded` in an explicit order (physics before view). Keep the core-toggle path on revision polling.
5. Move call sites over one at a time, re-running the rescued `e2e_app` suite after each.
6. Wire subscriptions in `main.js`, not inside `createGraph`; the viewer has no physics.

**Keep:** `setCore` stays the only writer of `is_core`. `recluster` stays the only code that *computes* `cluster_color_id`, and a no-op recluster must not bump `revision`. Physics position writes must not bump the appearance revision, or tints retarget every frame. `writeBack` keeps calling `syncNodes()` + `updateEdgePositions()`, which recompute bounds.

#### 2.4.2 Modal and input state is spread over ~8 flags, and a Ctrl+S mid-connect leaves a frozen line — P2 · M (S for the bug)
**Where:** The effective state is the product of:
- `mode`, `busy`
- `menu.isOpen`, `editor.isOpen`
- overview mode
- `controls.isLocked`, `controls.enabled`
- flight `enabled`

**Defect:** Ctrl+S is allowed while connecting (`interaction.js:450`), and on a first save `endModal()` forces `mode = 'idle'`. `sourceId` and the green halo stay, and the pending line freezes at its last endpoint until another connect is started or the source node is deleted. `editNode`/`prompt` have no `try/finally` around `await editor.open()`. Nothing throws there today, but a zero-field confirm (2.1.1) would, leaving `mode = 'editing'` for good: in the overview Tab is then dead and reload is the only exit. `beginModal()` also doesn't disable the overview's OrbitControls, so dragging behind a save prompt orbits the camera.
**Change:**
- **Quick (S):** have `endModal()` restore the mode saved at `beginModal()`, which keeps a half-made link through a save, and wrap every begin/await/end in `try/finally`.
- **Structural (M):** add `modal.js`, a stack with `push(kind, {suspendFlight, suspendOrbit}) → release` and `withModal(kind, fn)`.
  - Add `overview.setInputEnabled(bool)`. It must be **stored and re-applied inside `attach()`**, because OrbitControls is rebuilt on every activation.
  - Route all pointer-lock requests through one service with a single `pointerlockerror` handler.

**Keep:** `overview.enter` sets `mode = 'entering'` **before** `controls.unlock()`. Flight is deliberately not disabled when entering the overview. The editor stops keydown propagation.

#### 2.4.3 No error boundary: one throw in the render loop freezes the app silently — P1 · M
**Where:** `main.js` and `viewer.js` `setAnimationLoop` bodies have no `try/catch`. In three r180, `WebGLAnimation` calls the callback before scheduling the next frame, so one exception ends rendering for good. There are no `error`/`unhandledrejection` handlers. The async file flows are fire-and-forget. A font-load failure is swallowed (`labels.js:368`).
**Problem:** Any bug in a per-frame path looks like a hang, and the user reloads and loses the map (2.1.1). The key listeners and the DOM editor survive a dead loop, so **Ctrl+S would still work if the user were told**.
**Change:**
1. Wrap the frame body in `try/catch`. On error, stop the loop and show `#notice` (unhide `#overlay`): "Rendering stopped: <message>. Your map is still in memory — press Ctrl/Cmd+S to save it, then reload."
2. Add global `error`/`unhandledrejection` handlers that route to the status channel (2.4.8).
3. Add `.catch(reportError)` on every fire-and-forget flow, or `await` inside the keymap dispatch (2.4.4).
4. Once errors are caught and the loop can continue, wrap `bloom.render()`'s state changes in `try/finally`: camera layers, background, clear colour/alpha, `autoClear`, render target.
5. Put all of this in the shared shell (2.4.5) so exports get it too. Never include payload contents or passwords in error text.

#### 2.4.4 Keybindings live in five listeners, the help text in three hand-copied lists that have drifted, and Cmd-chords leak into flight — P2 · M
**Where:**
- Listeners: `flight.js:80-81`, `interaction.js:504`, `main.js:80-82` (Enter), `editor.js:61` (stopPropagation), `viewerInteraction.js:119`.
- Guards repeated per handler: `mode === 'editing'`, `mode !== 'menu'`, `controls.isLocked || overview.isActive`.
- Help: `index.html:19-32` lacks Scroll speed, save-as and connect/cancel. `viewer.html` has Scroll. The README table lacks Scroll speed.
- `interaction.js:477` Esc-while-connecting is dead code, because Esc always unlocks first.

**Defect:** `flight.js` `onKeyDown` ignores modifiers. Ctrl/Cmd+S with a password already set adds `KeyS` to `held`, and the camera flies backwards while the chord is down. On macOS, keyup is often not delivered for a key released while Cmd is held, so S can **stick** until pressed again. Cmd+A and Cmd+D feed strafing the same way. Needs confirming in a headed browser.
**Change:**
- Add `keymap.js`, a declarative registry: `{id, code|key, mods, when(ctx), run(ctx), help:{keys,text}, scope:['app','viewer']}`.
- One `window` keydown dispatches it against a context from the modal controller, awaiting `run` inside `try/catch`.
- Detect duplicate bindings in dev.
- Render both overlays' key lists, and a generated README table, from the registry.
- Make flight ignore keydowns with `ctrlKey`/`metaKey`, and call `releaseAll()` after any dispatched chord.
- Store `code` for positional keys and `key` for named keys (Escape, Enter). Letter *commands* on non-QWERTY layouts are covered in 2.8.

#### 2.4.5 `main.js`/`viewer.js` and `interaction.js`/`viewerInteraction.js` duplicate the app shell — P2 · M
**Where:**
- `main.js:17-33` ≈ `viewer.js:27-62`: constants, DOM lookups, scene/skybox/dust/bloom/flight setup, starting camera.

**Problem:** Every shell fix has to be made twice, and they have already diverged. A future error boundary or context-loss notice added only to `main.js` would be missing from exports.
**Change:**

- Shared `targeting.js`, `hud.js` and `cameraBlock.js`.

**Keep:** The export stays view-only by construction. The viewer opens on `overview.toggle()` after load → sync → camera. Frame order: flight → overview → physics → interaction → `view.update(elapsed, camera)` → `bloom.render()`.

#### 2.4.6 "View-only by construction" and the clustering stub alias are enforced by nothing — P2 · S
**Where:** `graph.js:21` statically imports `clustering.js` (graphology + Louvain). `vite.viewer.config.js:21-31` aliases **only the exact specifier** `'./clustering.js'` to a stub. `build-viewer.mjs` checks outward references and markers, not what code is in the bundle. ### 2.5 Rendering robustness and performance

#### 2.5.1 No WebGL2 capability check: a dead "Click to fly" screen — P1 · M
**Where:** `scene.js:13` `new THREE.WebGLRenderer(...)` is unguarded. three r163+ throws "WebGL 1 is not supported" or "Error creating WebGL context". `main.js:25`/`viewer.js:55` call it at module top level before any listener exists. The static overlay stays up, and clicking does nothing.
**Problem:** Hardware acceleration off, a blocklisted driver, a VM or RDP session, or an old Safari gives an inviting screen that never responds. This hits exported maps hardest, because their recipients never installed anything. Recent Chrome no longer falls back to SwiftShader automatically, so context creation is more likely to fail outright.
**Change:**
- `gpu.js` `createRendererSafely()`, shared by both entry points: `try/catch`. On failure, hide the prompt and key list, and show "This map needs WebGL 2, which this browser has turned off or does not support. Enable hardware acceleration or try another browser."
- After creation, probe once:
  - renderable half-float support; three enables the extensions itself, so only a device lacking both fails;
  - `maxTextureSize`;
  - the unmasked renderer string, to spot SwiftShader or llvmpipe.

  Feed the result into quality tiers (2.5.3). Without half-float, use 8-bit **sRGB** bloom levels (linear 8-bit bands) or turn bloom off.
- A precision probe is not needed; WebGL2 guarantees highp.
- `powerPreference: 'high-performance'` is a trade-off: it keeps the discrete GPU powered on dual-GPU Macs. Tie it to the high tier, not the default.

#### 2.5.2 WebGL context loss: after a restore the baked sky and every label are gone for good — P1 · M
**Where:** three handles `webglcontextlost`/`restored` itself, re-initialises its state and re-uploads anything with a CPU-side source. Two resources have none:
- **(a) The nebula** is baked once into a `WebGLCubeRenderTarget` (`skybox.js:189-215`) and comes back empty (black).
- **(b) The label atlas** is created with `data: null`, `dataReady = false` and filled only via `copyTextureToTexture`. It is reallocated zero-filled, every entry keeps its `cell`, and `labels.js:1047` only rasterises entries without one, so labels stay blank until they happen to be evicted.

**Problem:** Context loss is routine: driver resets, GPU switching on MacBooks, sleep, the GPU process restarting, too many contexts in other tabs. The map comes back with no nebula and no names. The graph is intact and Ctrl+S works, but a user who sees names vanish reloads and loses everything.
**Change:**
- `contextLoss.js`, registered **after** the renderer exists so three's handler runs first.
- On lost: show "Graphics were reset by the browser; restoring…" (unhide `#overlay`).
- On restored:
  - `skybox.rebake()`: factor `bakeNebula` so it can re-run. If the loss came from the bake itself (a TDR), rebake smaller or one face per frame.
  - `labels.invalidateAtlas()`: reuse the font-load loop at `labels.js:363-366`, i.e. `release(entry); entry.source = null`.
- Test headlessly with `renderer.forceContextLoss()` / `forceContextRestore()` in a **test page**. Never put `forceContextLoss` in the HMR dispose: the re-imported module would get the same lost context and never recover.

**Keep:** The atlas traps (4.4). Re-rasterising stays capped at 24 per frame.

#### 2.5.3 No quality tiers or adaptive resolution: the star ray-walk shader runs at full cost on every GPU — P1 · L
**Where:** The pixel-ratio cap is fixed at 2 and `antialias: true` is always on (`scene.js:13-14`). Three hard-coded ray families (`G = 4/7/11`), the detail threshold and a 96-step loop (`graphView.js:231, 241, 312-315`). Bloom `LEVELS = 6`, `BAKE_SIZE = 1024`, dust `COUNT = 1400`. The only measurements are from an Apple M3, where the worst case is already ~11 ms of a 16.7 ms frame. The plan names the levers but nothing uses them.
**Problem:** Integrated Intel/AMD GPUs, 4K displays at DPR 2 and tablets run several times slower, so flying near a core star drops to 15–30 fps, with no way to trade detail for speed. MSAA only benefits edges, halos and the pending line: stars render to a non-MSAA target and labels feather in the shader. This is the biggest blocker for the exported viewer, which runs on unknown hardware.
**Change:**
- **Start cheap:** a pixel-ratio cap setting and a `RAY_FAMILIES` define. Measure.
- **Then `quality.js`** with presets:
  - high: DPR 2, 3 families, detail [2,5], MSAA, 6 bloom levels, 1024 bake;
  - medium: 1.5, 3, [3,7], MSAA, 5, 512;
  - low: 1, 2 families (drop G=11), [4,9], no MSAA, 4 levels, 512 bake, 700 dust motes.

  Selection order: `?quality=` → a remembered override → automatic from 2.5.1's report.
- `antialias` and `depth` are **context-creation** attributes, decided before `createScene`; changing them needs a reload.
- Defines change on the single shared `nodeMaterial` via `needsUpdate`.
- **Adaptive DPR:** every ~2 s, step `setPixelRatio` in 0.25 increments with hysteresis. Each step reallocates the canvas and all bloom targets, so it is a one-frame hitch; keep steps rare.

**Keep:** Don't change the ray brightness, length or foreshortening distributions; the fitted average `0.1686·(1−ρ)^3.25·(1+0.4ρ)` is only valid for them. Every `8 × shimmer` stays whole. No bloom threshold.

#### 2.5.4 Device pixel ratio is read once — P2 · S
**Where:** `scene.js:14` calls `setPixelRatio` once. `resize()` only calls `setSize`.
**Problem:** Dragging the window between a Retina and a 1× display, or zooming the browser, leaves the drawing buffer at the old ratio: blurry going 1×→2×, and 4× the fragment cost of the most expensive shader going 2×→1×. On macOS moving between displays usually fires **no** `resize`.
**Change:** Call `setPixelRatio(min(devicePixelRatio, cap))` in `resize()`, and re-arm a `matchMedia('(resolution: ${dpr}dppx)')` change listener; the listener is required, not optional. Everything else reads the pixel ratio every frame, so nothing else needs wiring.

#### 2.5.5 Two depth buffers nobody uses cost up to ~150 MB of GPU memory — P2 · S
**Where:**
- **(1)** The renderer takes three's default `depth: true` with `antialias: true`, so the canvas carries a **4× multisampled depth buffer**, although *no material writes depth*. Bloom's exact star split depends on that fact. It is ~60–80 MB at 2880×1800 and ~100–130 MB at 3840×2160.
- **(2)** The sky-bake `WebGLCubeRenderTarget` keeps six 1024² depth renderbuffers alive all session, ~18–24 MB.

Other fixed costs: the sky cube ~25 MB colour, the label atlas ~10.7 MB, `starTarget` plus six half-float levels, and node capacity that never shrinks.
**Change:**
- Pass `depth: false` to the renderer and `depthBuffer: false` to the bake target. Pixel-check: frames should be identical.
- Document next to `createScene` that the canvas has no depth buffer, so any future opaque content needs its own target.
- Lower priority: let a wholesale `sync()` shrink node capacity (through `allocate()`). Leave edge buffers exact-size: zero-padding would create pickable phantom segments at the origin and distort the fog sphere.

#### 2.5.6 No in-app performance instrumentation — P2 · M
**Where:** No `renderer.info`, frame timing or stats panel. Every cost figure lives in build-plan prose. `bloom.render()` calls `renderer.render` 14+ times, so with `info.autoReset` the counters describe only the last pass.
**Change:**
- `perf.js`: `begin/end(name)` (no-ops unless enabled) plus a ring buffer of rAF intervals, reporting p50/p95/max.
- Wrap flight+overview, `physics.update`, `interaction.update`, and inside `view.update` separately ease / edges / labels, then `bloom.render`.
- Set `renderer.info.autoReset = false` and call `reset()` at frame start.
- An HTML HUD (never an in-scene mesh) on Backquote or `?perf=1`: percentiles, stage ms, draw calls, memory, drawing-buffer size and DPR, counts, tier, bake time, GPU string.
- `window.__atlasPerf` in dev for checked-in perf scripts.
- Don't make decisions from `EXT_disjoint_timer_query` on ANGLE/Metal; it reads ~12 ms per stage.

#### 2.5.7 The heaviest shaders compile on first use (e.g. the first node spawned) — P2 · S
**Where:** Meshes start invisible and three compiles lazily. Nothing calls `compile`/`compileAsync`.
**Trap the obvious fix misses:** the program cache key includes the output colour space, which is sRGB on the canvas and linear inside any render target, and stars are only ever drawn into `starTarget`. Compiling the scene against the canvas builds a star program that is never used.
**Change:**
- `bloom.precompile()`: with `setRenderTarget(starTarget)` bound, `renderer.compile(starRoot, camera, scene)`; then with the canvas bound, `compileAsync(scene, camera)`; then warm the full-screen quads.
- No visibility toggling needed: `compile()` walks `scene.traverse`.
- Set `renderer.debug.onShaderError` to show a visible notice, and keep `checkShaderErrors` **on**; `onShaderError` only fires when it is.
- Measure on Windows/ANGLE-D3D11 before investing further.

#### 2.5.8 The nebula bake is one heavy GPU job at startup — P2 · M
**Where:** `BAKE_FRAGMENT` makes 35 simplex evaluations per texel × 6 × 1024² ≈ 220M evaluations in one `CubeCamera.update`. 75–140 ms on an M3. Estimated 1–3 s on integrated GPUs; a TDR only on very weak ones.
**Change:**
- Tie `BAKE_SIZE` to the quality tier (512 below high).
- Spread over frames the simple way: one face per frame using **CubeCamera's own child cameras**, so orientation cannot drift, with a 64² synchronous pre-bake so the sky is never black.
- Expose `rebake()` (2.5.2) and record bake time in the perf HUD.
- **Do not** ship a pre-baked image cube: megabytes in every export, and image cubes need an x-flip the render-target path avoids.

#### 2.5.9 `graphView.js` (854 lines) and `labels.js` (1,256 lines) mix too much — P2 · M/L

**`labels.js` split:**

- `labels/atlas.js`: texture, scratch canvases, allocator, eviction, font hook.
- `labels/meshes.js`: instances and packing.
- `labels.js`: the orchestrator.

Start with layout and rules, which only move code. The plan's atlas numbers are **stale**: the code now uses 128×80 cells, a 40 px Jost raster, span 6 and 400 cells. Also, 400 cells is fewer than `MAX_LABELS = 512`, so the atlas is the real cap; document that.

**Keep:** Everything in 4.3 and 4.4.

### 2.6 Layout engine (physics and clustering)

#### 2.6.1 Move the force simulation into a Web Worker — P2 · L · schedule when >1,000-node maps are real
**Where:** `physics.js:352-355` do/while always runs at least one tick; a tick cannot be split. Measured: 800 nodes 7.7 ms/frame, 1500 nodes 22 ms, 3000 nodes / 12k edges 48–80 ms. `ALPHA_DECAY` fixes every run at 420 ticks.
**Problem:** Past ~1,000 nodes, flight, the menu and the crosshair drop to the tick rate for the whole 420-tick run.
**Change:**
- Structure:
  - `layout/forces.js` (pure);
  - `layout/layout.worker.js`, which owns the d3 simulation;
  - `physics.js`, a thin driver with the **same public API**, so `interaction.js` and `files.js` don't change.
- Load with `new Worker(new URL(...), {type:'module'})`.
- Messages:
  - **Seed:** `{type:'seed', gen, resetVelocity, ids, pos: Float64Array, collide, cluster, links, linkDistance, repelPairs, center}`.
  - **Frames:** transferable `Float64Array` buffers passed back and forth; drop any frame with a stale `gen`.
  - Keep Float64; Float32 would bring the float32-vs-float64 matching trap into the model. No SharedArrayBuffer, which needs COOP/COEP.
- **Pace the worker:** at most 4 ticks per frame the main thread has acknowledged, so small maps still settle visibly. Do not free-run.
- On `invalidate`, the worker keeps its own positions for ids it already has. Reseeding from the model, which lags by a frame, would rewind the layout.
- Keep an in-thread fallback driver built from the same forces module.
- Put it behind `?layoutWorker=1`, compare against the documented fixtures, then make it the default.

**Keep:** All of 4.2.

#### 2.6.2 Seed the layout's random source per run — P3 · S
**Where:** d3 builds one LCG per page. `reset()` never reseeds it. Jiggle fires only on exactly coincident coordinates, so layouts differ between a fresh tab and a long-lived one only in those cases.
**Change:** On `start()`, call `simulation.randomSource(seededRandom(LAYOUT_SEED))` **after** `linkForce.links([])` and **before** `simulation.nodes(active)`. This gives tests and the worker comparison an exact baseline. Don't sort ids for clustering: save/load already preserves insertion order.

#### 2.6.3 Louvain re-runs on every Balance even when nothing changed — P3 · S (step 1)
**Where:** `start()` calls `graph.recluster()` synchronously, which rebuilds a graphology Graph every time: 14–20 ms at 3000/12k, a guaranteed no-op when structure is unchanged.
**Change:** Add `structureRevision` (2.4.1) and skip when it is unchanged. Comment the precondition: this holds only while `recluster` and `load` are the sole writers of colours, so a future manual colour override must clear the skip.
Running clustering asynchronously in a worker **reverses** the documented rule that "the layout a run produces is that partition made visible" (`physics.js:317-320`). Only do that as an explicit decision alongside 2.6.1.

#### 2.6.4 Balance feedback — P3 · S
- B on a map with fewer than 2 nodes does nothing, because `toggle()`'s `false` is ignored. Say "balance needs at least 2 nodes".
- Every edit during a run reheats to alpha 0.5, and "balancing 85%" drops to ~10%, which reads as a restart. Keep the displayed progress monotonic within a run, or show "re-settling".

- Dust motes are **not** self-animating; they are fixed in world space and only move with the camera, so they need no reduced-motion handling.
- Freezing `pulseBeat` also freezes the per-star shimmer (same uniform), which is what reduced motion wants.
- FOV, flight damping, mouse sensitivity and invert-Y are settings (section 3). FOV changes just need `camera.updateProjectionMatrix()`: labels read `projectionMatrix[5]` and the overview fit reads `camera.fov` every time.

### 2.9 Cross-cutting gaps

These were found by a final pass looking for what the area reviews missed, then checked against the code like the rest.

#### 2.9.1 Several V2 recommendations need a secure context, and the advertised LAN deployment isn't one — P1 · M · **decide first**
**Where:** `run.py` binds `0.0.0.0` and advertises `http://<lan-ip>:5051`. Nothing in the code checks `isSecureContext`.
**Problem:** These browser APIs work only on HTTPS, `http://localhost`/`127.0.0.1`, and in Chromium and Firefox `file://`:
- `crypto.subtle` (2.2.5);
- the File System Access pickers (2.1.3, F10);
- service workers (2.2.4 option A);
- `navigator.clipboard` (F18, F25);
- `crypto.randomUUID`.

Each passes testing on `127.0.0.1` and then breaks for every device using the LAN URL: `crypto.subtle` is `undefined` there, so a WebCrypto save would throw and nobody on the LAN could save at all. `crypto.getRandomValues` is **not** gated, so collision-resistant ids (2.3.9) don't depend on this.
**Change:**
1. Choose the deployment model **before** starting any of those items, and record it as an ADR:
   - (a) localhost only;
   - (b) HTTPS on the LAN (2.2.1);
   - (c) a static, PWA or desktop build on a secure origin (2.2.4);
   - (d) keep LAN http, with a fallback for every gated feature.

   Options (b) and (c) also fix the plaintext-transport problem.
2. One startup probe in `src/platform.js`: `canWebCrypto = isSecureContext && !!crypto?.subtle`, `canFsAccess = isSecureContext && 'showSaveFilePicker' in window`. Feature code branches on these flags, never on feature presence alone.
3. When a feature is unavailable because of the origin, say so once ("Opened over http on the network: saving needs HTTPS or localhost") instead of throwing.
4. Add a Playwright project on a non-loopback alias. `--host-resolver-rules` mapping a name to 127.0.0.1 is *not* a secure context, so it really exercises the insecure path.
5. A reusable client-side key must be the PBKDF2 **base** key (`importKey('raw', pw, 'PBKDF2', false, ['deriveBits'])`). A derived key can't be reused, because the salt is fresh on every save.

#### 2.9.2 No supported-browser list, and concrete Safari/Firefox divergences — P2 · M
**Where:** Everything has been verified in Chromium only (plan:216-222, and the `file://` probe at plan:1165-1170). The code shows these divergences:
- **Label tracking.** `labels.js:340` sets `ctx.letterSpacing`, which Safari likely doesn't support (re-check current compat data). `textWidth()` (`:472-473`) still subtracts the tracking it assumes was drawn. In Safari every width is short (10.4 texels for cores, 3.6 for plain names), so the right halo is cropped, overlap rects are too narrow, and "…" lands at the wrong length.
- **Font metrics.** Firefox before 116 falls back to guessed ascent/descent (`:351-352`).
- **Pointer lock.** `PointerLockControls.lock()` drops the Promise `requestPointerLock()` returns, at three call sites: `main.js:76`, `viewer.js:126`, `overview.js:202`. Refusals become unhandled rejections, and the UI always shows the cooldown message, even for an unfocused document (`WrongDocumentError`, plan:1253-1256) or a sandboxed page.
- **File picker.** `accept='.atlasmap'` may grey out the file on some pickers (iPadOS Files is the known case).

**Change:**
- A README "Supported browsers" section: Tier 1 current desktop Chrome/Edge (fully tested); Tier 2 current Firefox (tested without lock); Safari best-effort, with its known issues listed; touch unsupported until F32.
- Feature-test `letterSpacing` at startup. If unsupported, use tracking 0 in *both* drawing and measuring.
- One `src/pointerLock.js` helper used at all three call sites: `canvas.requestPointerLock()?.catch(e => report(e.name))`. Map `WrongDocumentError`/`SecurityError` to "click the page first, or it is sandboxed", and keep the cooldown text for the rest. PointerLockControls still tracks `isLocked` through `pointerlockchange`, so bypassing `controls.lock()` is safe.
- Widen `accept` or drop it, and validate magic bytes after picking (2.3.6).
- Add Playwright `firefox` and `webkit` projects for the paths that need no lock: load, overview, save/open, export from `file://`, label pixel probes. Plus a manual checklist for locked flight, the menu and the editor.

#### 2.9.3 Labels mishandle non-Latin text and emoji — P2 · M
**Where:** `labels.js`:
- **Font loading.** `:360` calls `document.fonts.load('500 40px Jost')` with no text, which loads only the latin subset. Jost's latin-ext and Cyrillic faces are separate `unicode-range` files, and nothing else on the page (monospace DOM) ever triggers them.
- **Truncation and case.** `fit()` cuts UTF-16 code units (`:477-488`). `toLocaleUpperCase()` takes no locale (`:501`).
- **Rasterising.** Three passes composite with `'lighter'` — a black fill plus green shadow for the halo, then red glyphs — and the shader reads R as coverage and G as halo (`:557-567`, `:238-242`).
- **Input.** No `maxLength` on labels; no normalisation on commit.

**Problem:**
1. Names like "Łódź", "Brașov" or "Москва" in a map **opened after startup** are rasterised and measured in a system fallback face. One hover fixes the raster, because `setText` re-measures. But an entry evicted and later re-allocated is re-rasterised in Jost while keeping the fallback **width**, so the UV rect and quad disagree with the ink and the text is cropped or over-padded. Exports are less affected: the fonts are inline and the payload loads at startup.
2. Scripts Jost lacks (CJK, Arabic, Devanagari…) use Jost's ascent and descent, so tall marks and the halo clip at the cell edge.
3. **Colour emoji ignore `fillStyle`.** Each pass adds the emoji's own red into coverage and its green into the halo, giving a distorted monochrome blob.
4. Truncation can split surrogate pairs or ZWJ sequences.
5. Capitals depend on the viewer's locale ("İSTANBUL" on a Turkish machine), and RTL names get the "…" on the wrong side.

**Change:**
1. **Fonts.** In `setText`, when `!document.fonts.check(font, text)`, load `(font, text)` and then set `entry.source = null` so the entry fully re-measures. Releasing the cell alone keeps the stale width.
2. **Metrics.** Per-entry `actualBoundingBoxAscent/Descent`, clamped to the cell. Keep the per-cell baseline.
3. **Channel-safe raster.**
   - Draw text in white on a coverage canvas, then `source-in` fill red, so R = alpha whatever the glyph colours.
   - Build the halo from a **black** copy, or keep drawing the source off-canvas with only its green shadow landing, so red isn't added on each blur pass.
   - Composite with `'lighter'`.
   - Or, for v2.0, strip `\p{Extended_Pictographic}` and document it.
4. **Truncation and direction.** Cut on grapheme boundaries (`Intl.Segmenter`). Detect RTL and put "…" at the visual end.
5. **Case and input.** `toUpperCase()`, or a stored map locale. NFC-normalise labels on commit; don't rewrite loaded files. `maxLength` ≈ 200.
6. **Test.** A pixel-harness fixture of tricky strings (Łódź, Москва, 東京, مرحبا, a ZWJ family emoji, İstanbul, NFD é), opened via Ctrl+O *after* startup.

**Keep:** Every atlas trap (4.4).

#### 2.9.4 Browser shortcuts and Tab escape from panels: Ctrl+S inside a prompt opens "Save Page As" — P2 · S
**Where:** `editor.js:38-59` calls `stopPropagation` on every keydown but `preventDefault` only for Enter and multi-field Tab (`:51`, `entries.length > 1`). The window listeners never see Ctrl/Cmd+S, O, E or P while a field has focus. Single-field prompts: the edge label (`interaction.js:247`) and the Open password (`:324`, which runs unlocked). While the radial menu is held, the chord block is skipped (`:450`).
**Problem:**
- **Ctrl+S in a panel.** On the first-save password panel, pressing Ctrl+S again out of habit opens the browser's "Save Page As" for the HTML shell. The native dialog takes the lock, `onUnlock` cancels the editor, and the typed filename and password are gone. The user may even believe the `.html` they just saved is their map. The same happens editing a label, or with Ctrl+S while holding the menu.
- **Tab in a one-field panel.** Tab moves focus out of the page into browser chrome; in the unlocked Open prompt the rest of the password can then be typed into the address bar, where search suggestions send keystrokes to the search provider (verify per browser). In the locked edge-label prompt, Tab blurs the page and the edit is cancelled.

**Change:**
- In the editor, while open: `preventDefault` Ctrl/Cmd+S/O/E/P, and treat Ctrl/Cmd+S as **commit**; the save loop already re-prompts on bad input.
- Always `preventDefault` Tab inside the panel.
- A `focusin` guard returns focus to the panel.
- `preventDefault` (but don't act on) S/O/E chords in menu mode.
- In the keymap registry (2.4.4), "a modal owns the keyboard" becomes a property of the registry, not of each surface.
- Playwright: open the save panel, press Ctrl+S, assert no `text/html` download and that the values survive.

#### 2.9.5 Label atlas capacity: 400 cells, fewer than `MAX_LABELS`, and failures drop names silently — P2 · M
**Where:**
- **Capacity.** `labels.js:181-190`: 128×80 cells in a 2048² atlas is 16 × 25 = **400 cells** against `MAX_LABELS = 512`. A plain name takes 2–3 cells and a tracked capitalised core name often 4, so realistically 100–200 names fit.
- **Pinned cells.** `:867`/`:969` mark every entry still fading as `used = frame`, and `allocate()` can't evict those.
- **Silent drop.** A failed allocation sets `placed = false` with no signal (`:1047-1050`), and each failure re-runs the spread, filter and sort eviction scan.
- **Stale plan.** The plan (:672-693) still describes a 672-cell atlas and a capacity test that ran against it. A later session made cells bigger (`CELL_H` 80, `FONT_PX` 40, span 6), and nothing re-tested capacity.

**Problem:** Once always-on labels exceed capacity — a few hundred nodes in the overview, or several cores, each of whose neighbours is always-on — the lowest-priority names vanish without explanation or flicker as fades release cells. This gets worse exactly as maps grow.
**Change:**
1. Measure occupancy and allocation failures (2.5.6, 2.9.6), and add a large-map fixture.
2. Derive `MAX_LABELS` from `ROWS × COLS`, or document the real bound.
3. Let `allocate()` evict entries below ~0.2 alpha ahead of fully visible ones (the draw loop already skips cell-less entries).
4. Build the eviction victim list once per frame, lazily on the first failure.
5. Size the atlas from `maxTextureSize`:
   - 4096×2048 gives 800 cells at ~21 MiB with mips;
   - 4096² gives 1,600 cells at ~43 MiB with mips;
   - some backends store RG8 as RGBA8 and double these.

   Non-square needs separate `ATLAS_W`/`ATLAS_H` in `COLS`, `ROWS` **and** the UV maths (`:1098-1101`).
6. Longer term: a second atlas page, or a half-resolution far tier combined with the DPR work in 2.5.14.

#### 2.9.6 No local diagnostics for bug reports — P3 · M
**Where:** Nothing reads `renderer.capabilities` or the GPU string, and there are no `console.*` calls in `src`. The viewer shows one failure string. Pointer-lock refusals surface as anonymous "Uncaught (in promise)".
**Problem:** Exports are sent to other machines, and the app promises no network requests, so remote telemetry is out. A user-initiated local diagnostics copy is the only viable way to get the facts when "it's black on my laptop".
**Change:** `src/diagnostics.js`, shared by app and viewer, importing nothing editor-only:
- a ring buffer of the last 20 errors, with lock refusals tagged separately;
- `collect()` returning JSON with:
  - build version, user agent and `isSecureContext`;
  - `gl.getParameter(VENDOR/RENDERER)`, plus the unmasked strings in Chromium (`WEBGL_debug_renderer_info` is deprecated in Firefox);
  - `capabilities.maxTextureSize`, `maxSamples` and precision — **not** `isWebGL2`, which is hard-coded `true` in r180;
  - half-float support via `renderer.extensions`;
  - DPR, drawing-buffer size and `renderer.info`;
  - graph counts, atlas occupancy and frame percentiles.
- **Never** labels, notes, filenames or the password.
- Shown from a help key as a pre-selected read-only textarea, which works on http LAN origins and `file://`, where `navigator.clipboard` may not.
- Document the bug-report procedure in the README.

#### 2.9.7 The renderer requests no `powerPreference` — P2 · S
**Where:** `scene.js:13` uses three r180's default `powerPreference: 'default'`. Dual-GPU Windows/Linux laptops and Intel Macs with discrete GPUs may run the star ray walk (the dominant GPU cost) on the integrated GPU. Apple-silicon Macs have one GPU.
**Change:**
- `'high-performance'` for the editor, tied to the quality tier as 2.5.1 notes. Consider `'default'` for exports, so a recipient's battery isn't drained by a map left open in the background.
- Detect software rasterisers from the renderer string (`SwiftShader`, including `ANGLE (Google, Vulkan … SwiftShader`, `llvmpipe`, `Microsoft Basic Render`, `WARP`). Show a one-line notice and default to the lowest tier.
- Don't use `failIfMajorPerformanceCaveat` alone: it turns "slow" into "nothing".
- **Ship with or after context-loss handling (2.5.2)**: GPU switching on macOS can lose the context.

#### 2.9.8 Write a threat model — P3 · S
**Where:** `atlasfile.py:19-21` says the Fernet timestamp is "the one thing the container does not hide", but unpadded ciphertext length also reveals roughly how big a map is. The password lives for the whole session. Save As re-keys without the current password. Ctrl+E writes a plaintext copy with no confirmation. There is no SECURITY.md.
**Problem:** Without a written model, each V2 persistence feature makes ad-hoc security choices. Plaintext autosave to IndexedDB is the obvious risk.
**Change:**
1. A short threat-model section, in SECURITY.md or `docs/architecture.md`.
   - **Assets:** map content, notes, the password.
   - **Adversaries:** someone holding a `.atlasmap` file; a LAN observer; the server host operator; an export recipient; a person at an unattended open session; a malicious file.
   - **Not hidden:** the timestamp, approximate size, and *everything* for anyone at an open session, who can read the screen, press Ctrl+E or use devtools.
2. Correct the `atlasfile.py` docstring.
3. Make **"no plaintext at rest"** a hard invariant for autosave and recovery.
4. Optional, in order: an idle lock (F34, only once autosave exists); a one-time export confirmation listing what travels; size-bucket padding in format v2.
5. Don't sell "re-key requires the current password" as a security control. At most it guards against mistakes.

#### 2.9.9 The map has no identity: static tab title, export title from the download name, no metadata — P3 · S
**Where:** `index.html:6` is a static `<title>AtlasMap</title>`, and nothing sets `document.title`. The payload is nodes, edges and camera only. The export `<title>` comes from the session filename, e.g. "map (1) (1)".
**Change:**
- Set `document.title` to "`name` · AtlasMap", with "•" while dirty (2.1.1).
- An optional `meta: {title, created, modified}` block, under B2. **`files.js` must hold `meta` in its closure** and restore and emit it, because `graph.load` reads only nodes and edges; otherwise an open-then-save drops the title.
- Offer a title field on first save.
- The export uses `meta.title || filename stem` and shows it in the viewer HUD.
- Decide per the threat model (2.9.8) whether `modified` is sensitive.

#### 2.9.10 Error messages are prose, not codes — P3 · S
**Where:** `files.js` `errorFrom` passes the server's English sentence (or "server returned N") straight to the HUD. A wrong password is recognised only by HTTP 401. User-facing sentences are written in nine files across two languages.
**Problem:** An unsupported-version file can't get an "update AtlasMap" action. When crypto moves to the browser (2.2.5), every message must be rewritten, and Python and JS wording will drift apart.
**Change:**
- An error-code enum in the `format/` layer: `wrong_password`, `not_atlasmap`, `unsupported_version`, `payload_not_graph`, `too_large`, `server_unreachable`, `template_missing`.
- The server returns `{error, code}`; `PayloadError` carries `code`.
- `src/messages.js` maps codes to HUD text.
- Keep the 401-means-retry behaviour.

#### 2.9.11 Still-image capture and print constraints — P3 · M (technical notes for F31)
- `toBlob` must run in the same task, right after `bloom.render()`; the canvas has no `preserveDrawingBuffer`.
- The HUD, crosshair and overlay are DOM and never appear in a canvas capture. Only in-scene transient state needs hiding for the capture frame: `view.setHover(null)` and `view.setPending(null)`.
- For high resolution, raise the pixel ratio, not the CSS size. `bloom.render()` resizes its own targets from the drawing buffer every frame.
  - Clamp to `MAX_RENDERBUFFER_SIZE`/`maxTextureSize`.
  - Pause flight and physics, and restore in `try/finally`.
  - Known limit: labels are rasterised at 40 px, so at ≥2× near labels turn soft (2.5.14).
- Printing: `@media print` hides the DOM chrome, and `beforeprint` swaps in an `<img>` of a fresh capture, because a WebGL canvas without a preserved buffer prints blank.
- Works in the viewer too, which needs its own tiny download helper (B10).

#### 2.9.12 HTML shell hygiene — P3 · S
- **Favicon.** There is none, so every page load adds a 404 to `run.py`'s 4xx counter and "Recent" list, which hides real client errors.
- **The build guard trap.** `build-viewer.mjs:98-101` rejects *any* `href="…"`/`src="…"`, including `data:`, so an inline favicon would fail `npm run build`.
  - Relax the guard to exempt `data:` only; it must still reject `http(s)://`, `//host` and relative paths, and it also scans the inlined JS.
  - Or serve a real `/favicon.ico` for the app from Vite's `public/` directory and leave the viewer without one.
- **`<noscript>`.** Add one inside `#overlay` in both HTML files: "This map needs JavaScript and WebGL2. Open the file in a desktop browser (Chrome, Edge or Firefox)." An export previewed where scripts don't run (mail previews, file-sync web views) otherwise shows "Click to fly" over a blank page.
- **Colour.** `<meta name="color-scheme" content="dark">` and `theme-color #05060a`.
- Keep the zero-network property and single-occurrence markers (4.6).

#### 2.9.13 Export delivery: large inline-script `.html` attachments may be blocked — P3 · S · verify before acting
**Where:** An export is a 638 KB `.html` with ~580 KB of inline module script (plan:1231). Organisation attachment filters and "HTML smuggling" heuristics on gateways and endpoints can quarantine that shape. Outlook's default blocked list does not include `.html`, so this depends on configuration and **cannot be verified from the repo**.
**Change:**
1. First, send a real export through the channels actually used (Gmail, Outlook/Exchange, Slack/Teams, iMessage/AirDrop) and record what happens.
2. Document the result in the README ("some mail systems block .html attachments; send through file sharing or zip it").
3. Only if blocking shows up, add "Export .zip". `CompressionStream` does **not** produce a zip, so hand-write a store-only zip (local headers, central directory, CRC32; ~60 lines). Note that zipped HTML is scanned too.
4. A hosted viewer that loads small `.atlasview` data files would fix delivery and let the viewer update centrally. But it gives up the "no server, nothing fetched" promise, so it is an explicit product decision, not a mitigation.
5. In every format, keep notes out and apply the allowlist (2.3.3).

1. **Daily knowledge gardener** — a private second brain that grows to thousands of nodes over months.

### 3.1 V2.0 — must have

Suggested build order: **F9 → F8 → F2 → F1 → F6 → F7 → F5 → F4 → F10 → F3**.
- The first two unblock trackpad users and stop key collisions.

#### F1 Undo and redo — value high · L · all three users
**Today:**
- No undo anywhere (deferred at plan:1091).
- Delete is a 32 px flick on the left wedge. It removes the node, every connection and its notes, with no confirmation.
- Balance rewrites every position and cluster colour, which destroys a layout the user had memorised.
- The only safety net is an older saved file, and opening it replaces everything.

**What users get:**
- Ctrl/Cmd+Z undoes; Ctrl/Cmd+Shift+Z redoes (also Ctrl+Y on Windows/Linux; **not** Cmd+Y on macOS, which opens Chrome's History).
- One entry per action: spawn, connect, delete node (the same id, fields, position, core flag, colour and every connection come back), delete edge, text edits, core toggle, and later move, pin, direction and type.
- A whole Balance run is one entry. Undoing it stops a run in progress and puts back every position and colour.
- Works while flying and in the overview. Never while a menu or panel is open, so native text undo inside fields still works.
- HUD: "undo: delete node Budget (3 links)", "nothing to undo".
- Capped at ~200 entries, cleared on open or new map, never written to disk.

**How it fits:**
- B1, including `restoreNode`/`restoreEdge` that re-insert under the **original ids**. Star pulse and tint and edge mote phase are hashed from ids, so a restored item looks identical.
- Redo of an add restores the recorded id rather than calling `addNode` again. `mintId` already skips taken ids.
- **Balance:** snapshot `{id: [x,y,z,colour]}` plus `clusterCount` in `physics.start()` before `recluster()`. Undo calls `physics.stop()`, writes positions, then `view.syncNodes()` + `updateEdgePositions()` (which recompute bounds), then bumps `revision` so tints ease.
- If the undo removes the hovered node or the connection source, clear hover and cancel the connect.
- The history index doubles as the dirty counter (F2).
- The viewer must not import `history.js`, and `graph.js`'s restore primitives stay dependency-free.
- Unit-test history and the restore primitives in Node.

**Needs:** 2.4.1, 2.4.10, 2.4.2, 2.7.1. Interim delete confirm until then: 2.8.4.

#### F2 Unsaved-changes guard, dirty indicator and New map — value high · M · all
**Today:** See 2.1.1. Close, reload, crash, or Open-then-pick all silently discard work. Nothing shows the map is unsaved, and starting fresh means reloading.
**What users get:**
- HUD idle line: "map.atlasmap · unsaved · 12 nodes · 18 edges"; the tab title gets a "•".
- While dirty, the browser's own "Leave site?" dialog appears; browsers don't allow custom text.
- Open on a dirty map first asks: "unsaved changes in map.atlasmap · S: save first · D: discard · Esc: cancel". Save-first continues to the picker only if the save succeeds.
- **New map**, from the map menu (F8) or Ctrl/Cmd+Alt+N. Ctrl/Cmd+N can't be intercepted, and Ctrl+Alt is AltGr on some Windows layouts, so the menu entry is the main route. It goes through the same guard, then clears graph, filename, password, physics state and undo history.

**How it fits:**
- Dirty = history index ≠ index at the last successful save or open. Record the save index *before* the request (2.1.1).
- `files.js` gains `markClean()`, `isDirty` and `reset()`.
- New map follows `applyPayload`'s order: `graph.load({nodes:[],edges:[]})` → `physics.reset()` → `view.sync()` → `history.clear()` → cancel connect/hover → `overview.refit()`.
- The confirm is B4's keyed-choice panel.
- `beforeunload` lives in `main.js` only, never in the viewer.

**Needs:** F1 (or the interim counter in 2.1.1), 2.1.2, 2.4.8.

#### F3 Encrypted autosave and crash recovery — value high · M · all

## 4. Invariants no change may break

A seed for `docs/invariants.md`. Each rule is load-bearing and already cost at least one debugging cycle.

### 4.1 Model and persistence
1. `is_core` changes only through `graph.setCore()`, never by assignment; otherwise nothing resizes.
2. `recluster()` is the only code that computes `cluster_color_id`. `addNode` initialises it to 0 and `load` copies it. A re-run over an unchanged graph must not bump `revision`.
3. `graph.load` validates everything into local Maps and only then **refills** the live `nodes`/`edges`/`incident` Maps. It never reassigns them, because the view and physics hold references.
4. Positions are strictly finite on load (`requireFinite`). Never coerce with `Number()`: `Number(null) === 0` parks a damaged node at the origin.
5. Wholesale replacement order: `graph.load` → `physics.reset()` → `view.sync()` → camera → `overview.refit()`. Edits use `syncNodes`/`syncEdges`, which ease; only a wholesale replace uses `sync()`, which snaps sizes and resets labels.
6. `toPayload()` returns copies, because physics rewrites x/y/z every tick.
7. Credentials are adopted only after an Open succeeds. Password fields are never trimmed. The first save confirms the password.
8. The camera round-trips as `camera.rotation` in XYZ order; `PointerLockControls` works in YXZ, and the conversion is exact both ways.

### 4.2 Physics
1. `forceSimulation(nodes, 3)`; the dimension count defaults to 2.
2. Seed order: `linkForce.links([])` → `simulation.nodes(active)` → `linkForce.links(...)` → `edgeRepel.edges(...)`. `forceLink` throws on an unknown id.
3. Physics runs on proxy bodies keyed by id, never on model nodes; d3 stamps `index`/`vx`/`fx` on whatever it's given.
4. `body.collide` is set before `simulation.nodes()`, where forceCollide caches it. `body.cluster` is read per tick.
5. `forceCenter` is retargeted to the current centroid on every seed.
6. Every structural change calls `physics.invalidate()`. `invalidate()` never reclusters; only `start()` does.
7. The single-cluster guard: `forceCluster` does nothing when fewer than two clusters have bodies.
8. Edge repulsion is phantom bodies through `forceManyBody` (Barnes-Hut). A uniform grid degrades to brute force exactly in the dense case this force exists for.
9. `physics.update()` runs before `interaction.update()` in the frame.

### 4.3 View and instancing
1. After every instance-matrix write, null `nodeMesh.boundingSphere` **and** `boundingBox`. Culling and picking only recompute null bounds.
2. After every edge position write, recompute `LineSegments2` bounds (box **and** sphere), or edges become unpickable.
3. Anything hung on the node mesh (`STAR_LAYER`, `renderOrder = 1`, `DynamicDrawUsage`, hand-set geometry bounds, new attributes) is set **inside `allocate()`**, or it disappears when capacity crosses 256/512/….
4. Swap-remove walks slots backwards. Per-node view state is keyed by **id, never slot**.
5. Star phase, rate, seed and tint, and edge mote phase, are hashed from ids, so ids are never rewritten.
6. `writeMatrices` skips ids missing from the model, because easing can run between an edit and the caller's sync.
7. The star mesh is on `STAR_LAYER` (1), edges on 0, labels on `LABEL_LAYER` (2). The camera stays on layer 0 outside `bloom.render()`. Nothing writes depth, and stars are additive and drawn exactly once, which is what makes the bloom split exact.
8. `bloom.render()` is the only supported way to draw a frame. The MSAA canvas is drawn last and in one go, because leaving it and coming back costs ~0.9 ms.
9. No bloom brightness threshold; a threshold amplifies sub-pixel flicker.
10. `labels.js` assumes a perspective camera (depth from view-space z; px scale from `projectionMatrix[5]`).
11. `PointerLockControls` rebuilds orientation from a YXZ euler on every mouse move. Any camera pose handed back to flight must have zero roll and stay off the poles (`POLAR_MARGIN`).
12. `overview.enter` sets `mode = 'entering'` before `controls.unlock()`. A fresh OrbitControls is created per activation.
13. The pulse clock wraps at 28.8 s on the CPU. Every `8 × shimmer` must be whole, and the fitted ray average is only valid for the current ray distributions.

### 4.4 Label atlas
1. Scratch canvas textures must **never** be rendered or `initTexture`'d. `copyTextureToTexture` takes the canvas `texSubImage2D` path only when three has never seen the source.
2. `atlas.premultiplyAlpha = true` is set **after** `initTexture`.
3. `generateMipmaps` is true at first upload; during a flush it is true only on the frame's last copy.
4. The atlas has `data: null` and `dataReady = false`. Cell edges fall on multiples of 16. At most 24 rasters per frame. Entries still fading keep `used = frame` so eviction skips them.
5. Sticky quadrants: a label changes quadrant only from alpha 0.

### 4.5 File format
1. `atlasfile.VERSION` pins the KDF parameters: PBKDF2-SHA256, 600,000 iterations, 16-byte salt. Changing any of them without a new version branch makes every existing file fail as "wrong password".
2. Salt is fresh on every save. Wrong password and a tampered file stay indistinguishable. 401 is only for a wrong password.
3. `json.dumps(..., allow_nan=False)` — though see 2.1.4: browser saves never reach it.
4. `VERSION` means container and crypto only. Payload shape gets its own `schema` (2.3.1).

### 4.6 Export and viewer
1. Nothing reachable from `viewer.js` imports `interaction.js`, `editor.js`, `radialMenu.js`, `files.js`, `physics.js` or `clustering.js`. The export is view-only by construction.
2. Every splice uses a replacement **function**, never a string, because of `$&`.
3. The template contains each `__ATLASMAP_*__` marker exactly once. No marker literal may appear in the viewer bundle: the module script sits in `<head>` before the payload tag, and `replace` fills the first occurrence.
4. `<` in the payload becomes `<`. The bundle's own `</script` becomes `<\/script`.
5. Node `notes` never leave in an export.
6. The assembler fails the build on any outward reference.
7. Chrome grants pointer lock to `file://` documents, and the whole export design rests on that.

### 4.7 Input
1. Ctrl/Cmd chords match `event.code` and `preventDefault` before the browser sees them, even on repeat.
2. Pointer lock is never released for a menu or edit. It is released deliberately before a native file dialog. Chrome refuses re-lock for ~1.25 s after Esc.
3. The editor stops keydown propagation, so typing never reaches flight.
4. No filler or marketing copy anywhere in the UI (plan:1093-1095).

### 4.8 Test harness
1. SwiftShader frames can outlast wall-clock waits, so wait on rAF counts.
2. Headless pointer lock must be faked, and switchably, so Tab really releases it. Headed Chrome needs `page.bringToFront()` before the lock click, or it throws `WrongDocumentError`.
3. Instance matrices are float32 and model positions float64, so match by nearest position, never equality.
4. Sampling a glow or a glyph means rendering that layer **alone**.
